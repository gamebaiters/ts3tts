# v1.1.1 — autostart regression hotfix

v1.1.0 flipped `Settings::autostart`'s C++ DEFAULT from `true` to `false`, but `Settings::load()` reads `s.value("autostart", d.autostart)` — an EXISTING install already had `autostart=true` persisted in `QSettings("GameBaiters","TTS")` from before this fix (the only value it could ever have saved, since the old default was `true`), so the new C++ default never applied to anyone who had used the plugin before. Symptom: "engine keeps showing green/started every time I open it without me turning it on."

Fix (`core/Settings.h`/`.cpp`): one-time migration, same pattern already used for the v1.1 Italian-default language migration. New field `autostartMigrated` (persisted alongside `autostart`); `Settings::load()`'s sanitise/migrate section force-sets `autostart = false` exactly once when `!autostartMigrated`, then sets the marker so any later explicit choice (via the power button or Settings checkbox) sticks normally. `Controller::startup()`'s existing `saveNow()` (already there for "first run after an update: persist the migrated layout") persists the marker immediately.
