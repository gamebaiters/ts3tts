## Root causes found
- v1.4 installer required a system Python 3.12 (the new Windows had 3.14 only) and ran in a console.
- An engine venv made from a system Python is dead after reinstalling Windows ("No Python at ..."), yet `BackendProcess::resolve` called it installed → now `pyvenv.cfg` is checked.
- Engine code refresh compared only `__version__`: same version with new files (the stock voices) was never copied → content digest (SHA-1 over the tree).
- PowerShell: `$null` → `""` in `File.Replace`; `Register-ObjectEvent` handlers do not run inside a wait loop; Qt reads without `FILE_SHARE_DELETE` so `File.Replace` needs retries; `CMake Warning` on stderr killed `build_local.ps1` (`$ErrorActionPreference=Stop`) → merged inside cmd.
- Update helper: `tasklist` table output truncates image names > 25 characters → `/FO CSV`.
- `build_local.ps1` had a hard-coded `F:\VisualStudio 2022` → vswhere.

## Regression caught before release: +0.5 MB per plugin load
10 Kokoro cycles with `--trim`: v1.5 12.7 → 20.4 MB (cycles 2-10, monotonic) vs the v1.4 DLL from the TeamSpeak folder 12.0 → 15.6 MB (A/B, same harness). Cause: `Updater` created a `QNetworkAccessManager` at every init even with the automatic check off (Qt 5.15 starts its bearer/network-configuration machinery). Created lazily now → 9.6 → 15.8 MB, cycles 7-10 flat. Rule: no QNAM until a request really runs ([[crash-safety]]).
