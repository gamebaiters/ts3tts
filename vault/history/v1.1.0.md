# v1.1.0 — off by default, power button, tail fix, Soundboard interop

Companion release to GameBaiters Soundboard v2.4.0. See [[audio-bridge]].

## Engine on/off

- `Settings::autostart` default flipped `true → false` (`core/Settings.h`). `Controller::startup()` already branched on it correctly — the only bug was the default value itself, so existing users who already have `autostart=true` persisted keep their choice (this only changes fresh installs / never-saved settings).
- New `EnginePowerButton : public QToolButton` (`ui/TtsWindow.h/.cpp`), next to the status text. Three painted states (`Mode::Off/On/Intermediate`, no Qt5::Svg — painted glyph like `StatusDot`): grey/green/amber, mapped from `Controller::Backend`: `NotInstalled|Stopped→Off`, `Ready|Busy→On`, `Installing|Starting|Loading|Error→Intermediate` (deliberately collapsed — the button is a simplified 3-state summary, the status text above still shows the fine-grained state). Click routes to `openEngineSetup()` / `startBackend()` / `stopBackend()` depending on state; `stopBackend()` is safe to call from any state (used as "cancel" mid-Starting/Loading too).

## DSP tail / ring-out

`TtsAudio::pumpOnce()`'s ring-out was never actually unbounded — a hard `kMaxTailBlocks = 300` (3 s) cap already existed, cut short by a quiet-detector (`peak < 8` for 20 blocks = 200 ms). The real bug: `chainRings = m_dsp.isActive() || pitchOn` armed the FULL 3 s hold for ANY enabled sandbox stage, including ones with no tail at all (EQ, compressor, gate...) — `SlotDsp::isActive()` just means "the sandbox is on", not "a tail-producing stage is on". Fixed: `hasTailStage` now checks the SPECIFIC stages that can still be producing sound from silent input (`reverbWet > 0`, `delayEnabled&&delayMix>0`, `chorusEnabled&&chorusMix>0`, `flangerEnabled&&flangerMix>0`, `flangusEnabled&&flangusMix>0`, `phaserEnabled&&phaserMix>0`, `vfxEnabled` for VoiceFx's own pitch/formant grain windowing) — everything else now cuts the tail immediately with the phrase, same as no DSP at all.

## Soundboard interop

If the GameBaiters Soundboard plugin is also installed, `TtsAudio::onCapture` detects it via the shared bridge (`bridge->soundboardFresh()`) and stops writing the shared TS3 capture buffer itself — see [[audio-bridge]] for the full mechanism (Soundboard becomes the single writer, TTS's audio + mic policy published via `GbBridge::Shared::publishTts()`). Solo installs (no Soundboard) are completely unaffected — falls straight back to the pre-v1.1.0 direct-write behaviour.

Related: [[audio-core]], [[ts3-integration]], [[audio-bridge]]. Soundboard vault: `history/v2.4.0.md`.
