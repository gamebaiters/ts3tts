# v1.4.0 — read my channel chat aloud, no more refused messages while the engine starts (2026-09-15)

Package `dist\gb_tts_1.4.0_win64.ts3_plugin` (supersedes the never-installed 1.3.0; includes the voice changer of [[v1.3.0]]).
Requests: "checkbox con stato salvato nelle impostazioni: tutti i messaggi che mando nel CANALE (non chat private) vengono letti a voce alta dal TTS, così chi non può leggere sente lo stesso" and "mandare i messaggi in chat con un prefisso è estremamente lento, ci ha messo 30 secondi".

## Read my channel chat aloud
- Settings › Text: "Read aloud the messages I write in the channel chat (private chats are never read)" → `text/read_channel_chat` (off by default, saved at once).
- `ts3plugin_onTextMessageEvent` (new export) → `gbtts::onTextMessage`: only `targetMode == TextMessageTarget_CHANNEL`, `fromID == getClientID(sch)`, not `ffIgnored`; returns 0 (never hides a message); the work is `deferCall`-ed out of the callback.
- `Controller::onOwnChannelMessage`: BBCode stripped (`[b]`, `[URL=…]`, `[color=…]`…), spoken on the server tab it was written in, no history entry, no chat echo. Our own "also write it in the chat" echoes are remembered (`m_recentEchoes`, 2 min) and skipped when the server delivers them back, so enabling both options does not read a message twice.

## The "30 seconds" chat echo — root cause
Not TeamSpeak flood protection. `speak()` refused a message while the engine was starting or loading its voices ("still starting, try again") and the chat echo was only sent on success: the text stayed in the box, the user pressed Enter again and again, and the echo went out once the engine was ready. The channel chat log shows it: TTS started 10:00:21, first `[TTS]` message 10:01:19, then 10:01:22 and four in the same second at 10:01:23 (repeated presses).
Fix: a message typed while the engine is starting/loading becomes a queued job (`Job::sent = false`, "waiting for the voice engine"), the chat echo and history happen immediately, `flushPendingJobs()` sends it on `voices` / `ready`; stop, disconnect and giving up after restarts cancel/fail it. A stopped or not-installed engine still refuses with a notice.

## Measured (host harness on the real DLL + Kokoro backend)

- own private message: 0 frames · someone else's channel message: 0 frames · own channel message with BBCode: 72 235 frames, logged 23 characters (tags stripped)
