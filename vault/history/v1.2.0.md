# v1.2.0 — one engine at a time, per-engine voices, lifecycle proven (2026-09-15)

Package `dist\gb_tts_1.2.0_win64.ts3_plugin`. Request: "migliora la UI/UX per tutti i modelli e tutte le voci, scegliere nelle impostazioni quale motore far girare e fuori solo le voci di quel modello; quando TS crasha/si chiude tutto chiuso correttamente senza memory leak; salvare le impostazioni SEMPRE".

## What changed
### Engine model
- **The engine is chosen only in Settings** (`Controller::setEngine`): one card per engine (description, measured cost, availability + reason, "Active — N voices"), then the options of the selected engine only (`QStackedWidget`: Qwen size/step/prefill/expressiveness/idle/free GPU/manage voices · Kokoro variant · Supertonic steps). Leveler moved to Audio.
- `setEngine` stops current messages, saves, clears the voice list, reconfigures; if PyTorch is loaded and the target is light it **restarts the backend directly** (v1.1 did configure + idle restart later).
- v1.1 "the voice selects the engine" removed: `setVoice` refuses a voice of another engine (never loads a second engine behind the user's back).
- **Per-engine remembered voice**: `Settings::voices` (`voice/per_engine` map); v1.1 `voice/id` migrated to its engine and still written (downgrade-readable).
- Fallback when the chosen engine cannot run: plugin and backend use the same order (kokoro → supertonic → qwen), notice + saved.

### UI (shared wording/grouping in `ui/VoiceGroups.*` = `VoiceText`)
- TtsWindow: engine badge + "Change engine…", voice combo with ONLY the active engine's voices, grouped (Qwen: your voices / stock ⬇; Kokoro: by language, Italian first; Supertonic: women/men; ♀/♂), Listen button, language combo limited to `Controller::engineLanguages`, style field only for Qwen.
- VoiceDialog: active engine only, search box, group headers, "✓ in use"; design/clone tabs only with Qwen, otherwise an info page + "Choose the engine in Settings…".

### Backend
- `_voices()` lists the selected engine only; `voices` event carries `engine` (plugin drops lists of an engine it left). Metadata `gender`, `lang` (Kokoro names without region except US/UK/BR; Qwen stock speakers gender + native language).
- `speak` with another engine's voice → `job_error`; `voice_from_file` / `voice_design_*` require Qwen (`op_error`).

### Save always
Every `Controller` setter persists: discrete choices `saveNow()`, continuous controls `scheduleSave()` (300 ms) + `saveNow()` on slider release / editing finished; window geometry on move/resize; `Settings::save()` calls `sync()` and returns the status. TS3 callbacks only start the timer. Measured: **1.78 ms per save**.

### Close / crash
- `thread_local` scratch vectors in `TtsAudio` → members allocated once (TS3 audio threads outlive the DLL: TLS of an unloaded DLL leaks and its dtor would run into unmapped code).
- **`deferCall` (core/Defer.h) replaces every `QTimer::singleShot` functor** — bug 1 below.
- `BackendLink` connection **generations** + `dropPeer()`; extra loopback connections refused while one is authenticated.

## Bugs found (root causes)
1. **Queued `QTimer::singleShot` functor jumps into the unloaded DLL.** Found by the new host harness: execute AV at an unmapped address ← `QSingleShotTimer` timer event (nearest export printed as `QTimer::~QTimer+0x14a`) ← `QEventDispatcherWin32Private::sendTimerEvent`. Qt 5.15 parents `QSingleShotTimer` to the host's event dispatcher and keeps the context only as a `QPointer`: deleting the context skips the call, but the timer stays queued and its destructor runs `slotObj->destroyIfLastRef()` — the lambda's impl in our DLL. Trigger here: `ToolbarButton` retry (1500 ms, no toolbar); in TS3 also the 60 ms reposition pass and the 10 ms deferred init. **The Soundboard's `g_deferCtx` rule has the same hole** (it prevents the call, not the destructor jump). Reloading the DLL at the same base address hid it: an 8-cycle run crashed only after the final unload.
2. **Restart race**: `stopBackend` killed the process, its socket's late `disconnected` arrived after `startBackend` and killed the NEW backend (double start + 1.5 s). Fixed with generations.
3. A stray local connection to the loopback port evicted the authenticated backend before any token check.
4. Voice creation while the engine was not running: the op was dropped silently and VoiceDialog stayed busy forever → immediate `voiceOpResult(false)`.

## Measured
- `gbtts_settings_selftest` 22/22 (migration, round-trip, 1.78 ms/save) · `gbtts_audio_selftest` 15/15 after the buffer change.
- Backend `e2e_engines.py` **23/23**: Kokoro lists 41 `ko:` voices only, no PyTorch, refuses `st:`/`clone:` voices and voice design; Supertonic 10 `st:` voices; Qwen 12 voices, no `ko:`/`st:`.
- Host harness, no backend, **100 cycles with FreeLibrary, `--trim`** (pixmap cache cleared + heaps compacted before each sample), bisected:
  - load/unload only (`--no-init`): 3.0 → 3.0 MB, handles 181 → 181, second-half slope +0.000 MB/cycle;
  - init + shutdown, no windows (`--no-ui`): 3.2 → 3.6 MB, threads 7 → 7, GDI/USER 2/8 → 2/8, handles +16 once (cycle 50–75) then flat, slope +0.037 MB/cycle (noise band ±1.5 MB);
  - full (all three windows opened every cycle): 7.8 → 11.3 MB at cycle 50, **one step** to 21.5 MB by cycle 75, then 20.0 MB at 100; second-half slope **−0.005 MB/cycle** → a bounded host-side plateau (Qt caches that `QPixmapCache::clear`/`HeapCompact` do not return), not a per-cycle leak. Threads fall 11 → 5 (Qt/DirectWrite pool threads expiring). No crash at exit in any variant.
  - Before the trim option a raw 60-cycle run showed 7.5 → 24.6 MB; that is what triggered the bisection.
- Host harness, **real Kokoro backend**, 4 cycles with FreeLibrary: voice reached the playback callback (~95 k audible frames/cycle), backend gone ≤ 9 ms after shutdown, handles 311→311, threads 12→12.
- **Crash tests** (child client dies, no shutdown): TerminateProcess → backend dead 28 ms later; access violation → 21 ms (Kokoro); **Qwen 0.6B + access violation → 182 ms, GPU 5 691 → 2 928 MB (baseline 2 923) immediately**; a setting toggled 50 ms before the crash was on disk.
